## 사용 전 반드시 알아야 할 점
1. 이번 ZIP은 **소스코드 전체**를 포함하나 회사의 실제 데이터 원본은 포함하지 않습니다.
2. **기존 GitHub 저장소를 무조건 삭제하지 마세요.** 특히 `data/equipment.json`, `data/line-info-state.json`, 회사에서 추가한 파일, `.git` 폴더를 반드시 보존하세요.
3. `line-info.html` 내부의 `edseds`는 **시연용 확인 문자열**이며 실제 비밀번호 보안이 아닙니다. 프로덕션 환경에서는 사내 SSO/서버 측 인증을 사용해야 합니다.
4. GitHub Pages는 정적 호스팅입니다. 여러 사람의 데이터 공유 저장에는 저장소 API와 정식 권한이 필요합니다. 토큰을 HTML에 직접 넣거나 저장소에 업로드하지 마세요.
5. 페이지 숫자는 초기 가상 데이터입니다. 사내 원본 RAW가 있어야 실제 수치가 나타납니다.
6. 화면의 한 화면 맞춤은 모니터·브라우저 배율에 영향을 받습니다. 1920×1080, 브라우저 배율 100%에서 우선 최적화했고, 더 작은 화면은 내부 스크롤을 허용합니다.

## GitHub Desktop으로 일괄 반영 (초보자)
1. 현재 GitHub 저장소에서 **Code > Download ZIP** 으로 전체 백업을 받습니다.
2. 이 ZIP도 압축을 해제합니다.
3. GitHub Desktop에서 기존 저장소를 연 다음 **Repository > Show in Explorer**를 선택합니다.
4. **새 ZIP 내부의 파일들만** 복사해서 저장소 최상위에 붙여넣습니다. 기존 파일 교체 시 덮어쓰기를 선택합니다.
5. `.git`, `.github`, `data` 폴더를 삭제하지 않습니다. `equipment.html`은 기존 운영 페이지가 있다면 그 원본을 유지합니다.
6. GitHub Desktop에서 변경 목록을 확인한 다음 요약에 `EDS LinePlanning v4.2`을 입력하고 **Commit to main → Push origin**을 누릅니다.
7. GitHub Actions 배포 완료 후 `/line-info.html`로 접속하여 숫자 표시, 그래프 필터, 엑셀 업로드 검증, 변경 이력 등을 확인합니다.

## 동작 방식 (데이터 저장)
- 연결하지 않은 경우 브라우저 `localStorage`에 **그 PC에서만** 버전 이력이 남습니다.
- GitHub 저장소의 `data/line-info-state.json`이 존재하면 읽기를 시도합니다.
- 관리자에게 승인받은 GitHub API 쓰기 권한으로 수동 연결하면 업로드 후 변경 내용을 저장소에 커밋할 수 있습니다.
- 다른 사용자가 먼저 수정했으면 원격 버전을 확인해 충돌을 경고합니다.
- 실제 사내 운영에는 사내 보안 정책, 브랜치 보호 정책, 검토 승인 절차가 필요합니다.


## v4.2 화면 최적화 업데이트 (중요)
- 1437×770, 1600×900, 1920×1080 등에서 KPI **5개 한 줄**, 그래프 **3개 한 줄**이 기본입니다.
- 1450px 이하에서 KPI를 두 줄로 나누던 기존 규칙을 수정했습니다.
- 엑셀 업로드/버전 관리 패널을 상시 표시하지 않습니다. 상단 **데이터 관리** 버튼으로 열어 그래프 가로 폭을 확보합니다.
- Raw 데이터 위 **수정본 업로드**, **변경이력 보기** 버튼도 이전처럼 작동합니다.
- 아래 **작업 흐름/빠른 기능/품질 현황**은 평소 숨기고 **분석 도구** 버튼을 누르면 볼 수 있습니다.
- 그래프 내부 세로 스크롤을 최소화하여 10개 라인을 한 번에 보여줍니다. 첫 번째 면적 비교는 막대 위 건설면적 숫자, 하단 정확한 건설/클린/가용 수치 표를 유지하고 최대화하면 전체 목록을 확대합니다.
- 16개 메뉴, 46개 Raw 필드, 버전이력, GitHub 연동, 그래프-표 연계, 표 최대화/원래대로 기능은 기존 기능을 보존하며 개선했습니다.
- **한 화면 맞춤**은 모니터 크기에 따라 동작하며 창 크기가 작거나 브라우저 확대한 경우 스크롤이 일부 생길 수 있습니다.

## 브라우저만 이용해 v4.2 업데이트 (GitHub Desktop 설치 필요 없음)
1. 먼저 GitHub 저장소에서 `Code → Download ZIP`으로 백업하세요.
2. v4.2 ZIP을 압축 해제하세요.
3. GitHub 저장소 최상위의 `Add file → Upload files`를 클릭하세요.
4. ZIP의 최상위 파일들을 선택해서 업로드하고 `Commit changes`를 누르세요. 파일 덮어쓰기가 거부되면 해당 기존 파일의 수정 절차를 이용해야 합니다.
5. **`data/` 폴더와 기존 `equipment.html`, `.github/` 등은 삭제하지 마세요.** GitHub의 기존 JSON·과거 변경이력이 보존되어야 합니다.
6. 배포 완료 후 `/line-info.html`에서 `Ctrl+F5` 새로고침하고 브라우저 배율 100%로 확인하세요.

기밀자료 취급 시 회사 GitHub 저장소와 Pages의 실제 공개 범위·접근 권한을 확인하세요.


## v4.2 홈 / 라인 기본정보 통합 화면 수정
- 홈과 01 상세 페이지의 왼쪽 메뉴명을 **6개 그룹·16개 항목으로 동일**하게 통일했습니다. 링크는 동일한 업무 화면으로 이동합니다.
- 홈 통합 대시보드는 1437×770 / 1600×900 / 1920×1080 등에서 KPI 6개와 주요 분석 2개·하단 업무 3개가 최대한 한 화면에 보이도록 화면 높이와 폭에 맞춰 조정합니다. 작은 화면은 세로 스크롤을 허용하며 글씨를 과하게 축소하지 않습니다.
- 01 페이지는 **최대화 / 원래대로 버튼만** 유지합니다. 최소화 버튼과 축소 상태를 제거했습니다.
- 01 페이지 그래프 최대화 시 그래프 내용(막대, 수치, 층 구성, 히트맵)도 확대된 영역에 맞춰 채웁니다.
- Raw 표 최대화 시 모니터 가로·세로를 최대한 사용하고, 전체 46개 열은 **표 안의 가로 스크롤**로 볼 수 있습니다(모든 열을 한꺼번에 읽기 불가능한 크기로 압축하지 않음).
- ‘업로드·변경이력’ 사이드 패널은 기본 닫힘으로 그래프를 가리지 않습니다.
- 기존 설비현황·운영 데이터 (`equipment.html`, `data/...`) 보존: 이 ZIP에는 실제 업무 데이터 JSON이 들어있지 않습니다.
- 업로드 방식: Github 웹 `Add file → Upload files`, 기존 파일에 같은 이름이 있을 때 업로드 실패 시 파일을 직접 교체해야 할 수 있습니다. 기존 원본 백업 필수.
