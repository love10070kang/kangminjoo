# 03. 확정 디자인 시스템 및 모니터 크기 대응 요구사항

## 최우선: 사용자 승인 화면을 유지하며 개선한다

- 전체 컬러: 다크 네이비, 선명한 푸른 테두리, 청록·파랑·보라 포인트. 과한 장식보다 고급스러운 업무용 기업 대시보드.
- 메뉴: `nav.css`와 `reference/approved-sidebar.png` 참고. 홈과 01이 **동일**해야 함.
- 01 구조: `상단 검색 및 페이지 제목 → FAB/라인/층/동 등 필터 → KPI 5개 → 그래프 3개 → RAW Data 46열 통합표`.
- KPI 5개: 전체 라인 수, 관리 층 수, 건설면적 합계, 클린면적 합계, 가용면적 합계.
- 그래프 3개: 라인별 면적 비교(건설/클린/가용), 라인별 층 구성(최대 3층), 라인×층 가용면적 히트맵.
- 그래프마다 제목·축·단위·수치·범례 필수. 작은 화면에서 중요한 숫자를 숨기거나 한 화면에 들어가도록 무작정 줄이지 말 것.
- RAW 표 상단에는 최신 다운로드/수정본 업로드/변경이력/비교 등 기존 액션 보존. 관리용 패널은 기본 닫힘.

## 반응형 화면 수용 목표

| 모니터 뷰포트 예 | 동작 목표 |
|---|---|
| 1437×770 | KPI 5개 1행, 그래프 3개 1행, Raw 일부 행 보임. 메뉴 자체 내부 스크롤 |
| 1600×900 | 위 구조 유지, 숫자 읽기 쉬운 차트 및 Raw |
| 1920×1080 | 차트와 Raw 영역 여유 있게 확대 |
| 폭 1100px 이하 | 좁은 뷰포트: 필요한 스크롤/메뉴 점프 허용; 글자 가독성 우선 |

Windows 125% 확대 등 실제 보이는 CSS 뷰포트 크기가 달라져도 레이아웃이 찌그러지지 않아야 합니다. 특히 **KPI가 임의로 3+2 줄로 쪼개지고 차트 내용이 잘리는 문제**를 회귀 테스트합니다.

## '최대화 ↔ 원래대로' 두 상태만 존재

- **최소화 버튼은 사용자 요청에 의해 삭제**. 앞으로 다시 넣지 말 것.
- 일반 차트 → 최대화: 패널 외곽만 키우면 실패. 막대·축·숫자·히트맵 및 상세 레이블도 넓어진 컨테이너에 맞춰 재배치되어야 함.
- 일반 RAW → 최대화: 뷰포트의 가로·세로를 채우고 46열은 내부 가로 스크롤. 작은 글자로 46열 전체를 한 번에 욱여넣지 않음.
- 원래대로/ESC → 원래 배치 정확히 복구. 버튼 표기는 `최대화`/`원래대로`.

## RAW Sticky Table(강조: 기존 오류 재발 금지)

- RAW 헤더는 2줄: **그룹(식별, 사업장·건물, 공간...) + 필드명**.
- 세로 스크롤 시 2줄 모두 고정; **본문이 헤더 위에 겹쳐 나타나는 현상 금지**.
- 식별 3열 `라인 ID`, `라인명`, `층`은 **좌측에 고정**. 다른 열 가로 스크롤해도 움직이지 않음.
- 교차부(고정 헤더×고정 열)의 z-index가 본문보다 높아야 함. 현재 `line-info.html`의 `.raw-table thead`/`.sticky*` 규칙 참고.
- 다른 해상도/브라우저 확대/최대화 후에도 동일 동작. 두 줄 헤더 사이의 sticky top 값은 실제 그룹 헤더 높이를 사용.
- 마우스 휠/트랙패드/Shift+Wheel/스크롤바/표 최대화에서 확인.

## 디자인 변경 금지 사례

- 16개 메뉴 중 일부 삭제, 단어를 임의로 다른 이름으로 바꾸기.
- 승인받은 KPI/그래프/Raw 순서를 바꾸거나 불필요한 '작업 흐름', '추천 기능' 패널을 상시 추가.
- 기존 기능 대신 허위 버튼·비작동 데모를 놓아 완료된 것처럼 표시.
- 그래프 라벨을 숨기거나 단위를 생략하고 툴팁에만 넣기.
- 모바일 뷰에서 글자 8px 수준으로 축소해 억지로 맞추기.
