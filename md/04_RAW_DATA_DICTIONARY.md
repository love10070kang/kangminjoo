## 필수 업무 정의

- **행 단위**: 라인 내 1개 실제 층/구역/방(Bay/Room)에 대한 RAW 레코드. 라인당 최대 3개 층이지만 *실제로 존재하지 않는 층을 생성하지 않음*.
- **현재 고유 키**: 구현 코드의 `KEY` = `라인 ID + 층 + Bay + Room`. 이 키를 변경할 때는 이전 버전 호환/중복/누락 검사를 반드시 변경해야 합니다.
- **면적**: 건설면적·클린면적·가용면적은 서로 다른 의미. 가용률은 업무 정의와 분모(클린/건설 등)를 먼저 명확히 한 뒤 계산할 것. **공간 사용률과 동일하다고 가정하지 않음**.
- **0과 누락**: `0`, `미입력`, `해당 없음`, `확인 필요`를 구분. 특히 공란을 0mm/0kg으로 간주해서 설치 불가 또는 가능을 자동 판단하지 말 것. 현재 코드의 일부 숫자 유틸리티 함수는 빈 칸을 0으로 처리할 수 있으므로 운영용 판단에는 추가 검증 필요.
- **바닥/층고**: 허용하중·집중하중·진동·Access Floor·설치 가능 유효높이 등을 함께 점검. 단위 표시 필수.
- **반입구**: 1과 2를 각각 독립 규격/위치/제약으로 기록. 단순 개수만으로 적합성을 결론 내리지 말 것.
- **도면**: CAD 링크, 개정번호, 도면 기준일 보유. 승인 도면 판단은 파일 기준일이 아닌 승인 상태/검토 이력과 연동 필요(향후).
- **메타데이터 별도**: `최종 수정일`, `수정자`, `변경 사유`, `변경이력`, `자료 출처`, `BIM/As-built 링크`, `차압`, `Access Floor 유무`를 **46개 엑셀 RAW 열에 임의로 추가하지 않음**. 버전 메타데이터는 별도 저장. 다른 페이지 확장 계획과 혼동하지 말 것.
- **엑셀 파일**: `EDS_RAW_Template_v1_1.xlsx`은 수정용 표준 양식. 헤더와 열 순서 변경 금지. 실제 데이터는 기존 저장소 `data/line-info-state.json`/로컬 버전 데이터에 있을 수 있음.
- **레코드 수**: 시연 데이터 약 10개 라인/28개 층 행. 실제 회사 데이터가 아니라 가상 예시임을 명시. 숫자는 업무 기준이 아님.
- **자료 훼손 방지**: 업로드 시 열 검증, 중복 키, 예상치 못한 삭제, 변경/추가 구분. 누락된 기존 행을 임의 삭제하지 말고 검토/승인 시나리오를 별도 구현.

## 성능·데이터 처리

46열 × N행을 렌더링할 때, 원본 데이터의 열 이름과 형식 보존이 최우선. 1000건 이상에서는 가상 스크롤/서버 검색을 검토하되, 현재 시연 데이터에 없는 고급 기능을 구현된 것으로 표시하지 말 것.
